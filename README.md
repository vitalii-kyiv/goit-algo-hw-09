# Оптимізація видачі решти: Жадібний алгоритм vs Динамічне програмування

## Опис алгоритмів

### Жадібний алгоритм (`find_coins_greedy`)
Жадібний алгоритм працює за принципом вибору найбільшого можливого номіналу монети для кожного кроку. Це дозволяє швидко отримати результат, але не завжди гарантує мінімальну кількість монет.

**Переваги:**
- Простота реалізації.
- Висока швидкість роботи.

**Недоліки:**
- Не завжди знаходить оптимальне рішення (мінімальну кількість монет).

### Динамічне програмування (`find_min_coins`)
Метод динамічного програмування знаходить мінімальну кількість монет для заданої суми, обчислюючи оптимальне рішення для всіх можливих значень від 0 до потрібної суми.

**Переваги:**
- Гарантовано знаходить мінімальну кількість монет.
- Підходить для будь-яких наборів монет.

**Недоліки:**
- Споживає більше пам'яті та часу, особливо для великих значень суми.

## Порівняльний аналіз
Було проведено тестування на сумах 113, 217, 999 та 5000. Результати:

| Сума  | Жадібний алгоритм (монети) | Час виконання (сек) | Динамічне програмування (монети) | Час виконання (сек) |
|-------|----------------------------|---------------------|--------------------------------|---------------------|
| 113   | {50: 2, 10: 1, 2: 1, 1: 1} | ~0.000002          | {50: 2, 10: 1, 2: 1, 1: 1}     | ~0.000015          |
| 217   | {50: 4, 10: 1, 5: 1, 2: 1} | ~0.000002          | {50: 4, 10: 1, 5: 1, 2: 1}     | ~0.000020          |
| 999   | {50: 19, 25: 1, 10: 2, 2: 2} | ~0.000002          | {50: 19, 25: 1, 10: 2, 2: 2}  | ~0.000025          |
| 5000  | {50: 100}                   | ~0.000002          | {50: 100}                      | ~0.000100          |

**Висновки:**
- Жадібний алгоритм працює швидше, але підходить лише для випадків, коли набір номіналів дозволяє отримати оптимальний результат.
- Алгоритм динамічного програмування завжди дає найкращий варіант розбиття суми на мінімальну кількість монет, але споживає більше ресурсів.
- При малих та середніх сумах різниця у швидкості несуттєва, але для великих значень динамічне програмування може працювати повільніше.

## Висновок
Якщо важлива швидкість і набір монет дозволяє жадібному алгоритму працювати ефективно, його можна використовувати. Проте, якщо важливо мінімізувати кількість монет або набір номіналів складний, динамічне програмування є кращим вибором.
